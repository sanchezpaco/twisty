# Twisty — project rules

Twisty plans motorcycle routes from A to B that maximise the time spent on great twisty roads.
Motorways are fine for getting to the good stuff quickly; the planner trades extra time for curves.
See `PRD.md` for the product, `ROADMAP.md` for phases and `README.md` for setup.

## Language

- **Everything in the repo is in English**: code, identifiers, comments, commit messages, docs.
- **The app is localised** (English and Spanish): UI copy lives in `app/src/lib/i18n/`, `en.ts` is the source and
  every other language translates it. Never hard-code UI text in components.
- Spanish is only used in conversation with the user and in UI translations.

## Engineering principles

- **KISS**: the simplest thing that works. No speculative abstractions.
- **YAGNI**: don't build for hypothetical future needs. If the roadmap says "later", it waits.
- **Clean code**: small focused functions, intention-revealing names, no dead code, no commented-out code.
- Pure functions for algorithms (geometry, curvature, routing, planning); keep I/O at the edges.
- Comments explain *why*, never *what*. Match the comment density of the surrounding code.
- No magic numbers in algorithms: name tunable constants and keep them together at the top of the module.
- Prefer composition over inheritance; prefer data + functions over classes unless state is genuinely owned.
- Fail loudly on invalid input at boundaries; trust data inside the core.

## Repository layout

```
pipeline/   Python data pipeline: OSM extract -> twisty segments + compact routing graph
app/        Vite + Svelte 5 + TypeScript client (later wrapped with Capacitor)
data/       Raw downloads and intermediate files (git-ignored)
```

Pipeline output is written to `app/public/data/` (git-ignored, regenerated by the pipeline).

## Stack decisions

- **Pipeline**: Python 3, `pyosmium`, `numpy`, `pytest`. `osmium-tool` CLI for pre-filtering.
- **App**: Svelte 5 (runes), TypeScript (strict), Vite, MapLibre GL JS, Vitest.
- **Twisty overlay**: vector tiles (z0–12) cut from the pipeline's twisties by a Node script, `app/scripts/overlay-tiles.ts`
  (`make overlay`, part of `make data`). It is Node and not Python on purpose: it uses geojson-vt, the tiler MapLibre
  runs itself, so the tiles hold what MapLibre would cut at run time and the overlay keeps its picture
  (`make overlay-parity`).
- **Routing runs on the device**: a contracted road graph is shipped as a binary file and searched
  with Dijkstra in a Web Worker. No backend, no API keys.
- **Map**: OpenFreeMap vector tiles with a custom style, AWS Terrarium DEM for hillshade/terrain.
- **Place search**: offline index of Spanish towns and villages built by the pipeline (instant, as-you-type);
  streets and addresses on explicit request via Nominatim (its policy forbids search-as-you-type).
- **Output**: a Google Maps directions URL (max 9 waypoints).

## Commands

Use the `Makefile` (`make` lists targets): `setup`, `data`, `overlay`, `dev`, `test`, `web`, `apk`, `install`, `run`, `logs`.

```bash
cd pipeline && .venv/bin/pytest
cd app && npm test
cd app && npm run check   # svelte-check + tsc
```

The Android project lives in `app/android` (Capacitor). Native changes go there; web assets are synced into it by
`make android`, never edited by hand.

## Git

- **Conventional Commits**: `feat:`, `fix:`, `refactor:`, `perf:`, `test:`, `docs:`, `chore:`, `build:`, `style:`.
  Optional scope: `feat(planner): ...`, `fix(pipeline): ...`.
- Small, focused commits. Imperative mood, lowercase subject, no trailing period.
- Keep `ROADMAP.md` up to date: tick items when they land, add items when scope is discovered.
- Keep `PRD.md` in sync when product scope or requirements change.
- **The repo is public**: nothing private in any commit, screenshot or report (other projects, machine paths, device
  serials, account ids, the maintainer's places, trips or personal email). Machine-specific setup lives in the
  git-ignored `CLAUDE.local.md`. The history before 2026-10-23 stays in a private archive.

## UX bar

The app must be beautiful and a pleasure to use, not "a map with stuff on it".
Dark, cinematic map; the route is the hero. Smooth transitions, no jank on mobile.
Mobile-first layout (bottom sheet), desktop gets a floating side panel.

## The team

The director (the main Claude session) is the maintainer's delegate for day-to-day calls: what it approves is
approved, and it reports after. It coordinates and never implements. It talks to the maintainer in Spanish; anything
written to the repository stays in English.

Two kinds of agents:

- **Sessions** in herdr (workspace `twisty`), only for roles with continuous work. Two to start, split when the work
  demands it; `marketing` joined for the store listing (2026-10-19).
- **Subagents** defined in `.claude/agents/*.md`, for reviews and short tasks. Builders own code; reviewers are
  read-only and report findings.

### How work flows

- Plans come to the director for approval before anything is built. A decision the maintainer took, or anything that
  needs their eye (look, feel, route taste), goes to the maintainer with a screenshot or link.
- Every change lives on a branch in a worktree: `git worktree add ~/code/twisty-<topic> -b <topic>`.
- The director lands every branch on `main` (fast-forward after the gates); owners report the branch and sha.
- A review round produces one ranked list (blocker, major, minor) that the director routes to the owners. Nobody
  runs a duplicate review. A finding the maintainer discarded stays closed without new evidence.
- Gates: `cd pipeline && .venv/bin/pytest`, `cd app && npm test`, `cd app && npm run check`. Route quality is gated
  by the validation set once it exists (`ROADMAP.md`, Next up); the `road-scout` flags when a known great road stops
  being found.

### Sessions in herdr

The director starts, rotates and parks them (`herdr --skill` for the CLI), one tab per session in the workspace
`twisty`, named after the role.

- **Start:** `herdr tab create --workspace twisty --cwd ~/code/twisty --label <role> --no-focus`, then
  `herdr agent start <role> --kind claude --pane <root pane> -- --name <role> --model <model> --effort <level>`, then
  `herdr agent prompt <role> "/handon <role>"`.
- **Handoffs** live in `.claude/handoffs/` (git-ignored), one fixed name per role, never `latest`: `director`,
  `routing`, `app`, `marketing`.
- **Rotate** by handoff when a session passes about 35% context and is idle at a clean point: ask it for
  `/handoff <role>` with its open decisions in the file, check the file is fresh, start the successor, confirm it
  loaded the handoff, then `herdr tab close` the old tab. Let heavy jobs and subagents finish first. Never answer a
  session's approval or question dialog; ask the maintainer.
- **Park** a session with nothing to do: the machine is small and shared with other projects (details in
  `CLAUDE.local.md`).
- **Models and effort:** quality wins every tie. Cost is optimised only where quality is not sacrificed: Haiku 5.5 for
  mechanical chores (builds, installs, screenshots, running tests and reporting); Sonnet for implementation with a
  clear brief and checks; Opus for plans, reviews, route-quality and aesthetic calls, and anything that failed twice on
  a cheaper model. When a cheaper model's output is doubtful, or a judgment task fails once, escalate instead of
  retrying cheap. The director double-checks what cheap agents hand back before reporting it done. Sessions on Opus
  use `claude-opus-5-5[1m]` (the bare alias opens a 200k window). Effort is only `medium` or `high`, set at launch
  (`--effort`, the Agent tool's `effort` for subagents): `/effort` inside a running session rewrites the
  maintainer's global default in `~/.claude/settings.json`.

### Heavy jobs

`make data` (OSM pipeline, RAM-heavy), gradle and `make apk`, and the full test suites go through the machine's
heavy-job wrapper, which hands out a few slots shared with other projects (command and rules in `CLAUDE.local.md`).
While iterating run the related tests (`npx vitest run <files>`, `pytest pipeline/tests/<file>`); the full
`make test` once, at hand-back.

### Devices

Two phones are on adb (serials in `CLAUDE.local.md`). The **Huawei P smart 2019** is old and is the performance bar:
every performance claim is measured on it, and quality is never traded for speed. The **Z Fold** is the layout bar,
folded and unfolded. A phone may be shared with other projects: install and clear only `com.sanchezpaco.twisty`,
never another app or its data (the rules for each phone are in `CLAUDE.local.md`). One agent drives a phone at a
time; reviewers without a phone use `vite preview` at the phone's viewport (Huawei 360×780 dpr 3) in headless Chrome.

### Lessons from past runs

Read before briefing an agent; add a line whenever a run wastes a round trip.

- **Toolchain:** a stale system Python or `JAVA_HOME` breaks builds. Name the Python and the JDK
  (Capacitor 8 needs exactly JDK 21; gradle 8.14 does not run on 25) in every build brief; this machine's paths are in
  `CLAUDE.local.md`.
- **Preflight before heavy steps:** a build brief checks the toolchain (`python --version`, `java -version`,
  `osmium --version`, `adb devices`) first, so a 15-minute pipeline never runs before a 10-second failure.
- **Pre-approve the known fallbacks** in the brief (which JDK, which Python) instead of telling a cheap agent to
  stop on any error: an unknown error stops it, a known one does not cost a round trip.
- **Name every target device in the first brief.** A device added by message mid-run may be refused by the
  subagent's permission check; the director then does it or relaunches with the new brief.
- **Screenshots on the Fold:** `adb exec-out screencap -p` prepends a "Multiple displays" warning that breaks the
  PNG; use `adb shell screencap -p /sdcard/s.png && adb pull /sdcard/s.png <out>`.
- **Reports can arrive twice:** a finished agent sometimes repeats an older hand-back; check its content before
  acting on it.
- `cap sync` regenerates `app/android/capacitor.settings.gradle` and `app/android/app/capacitor.build.gradle`;
  commit them when plugins change, or the next build shows a dirty tree.
- **Tester APK paths:** a session's "final APK" may live in its scratchpad, not in its worktree's `dist/`. Ask for
  the absolute path, check it exists before telling another session to install it, and after landing build the
  tester APK from `main` so the phone never stays on a bench-hook build.
- **Reports via the hand-back tool:** to commit a subagent's long report verbatim, extract it from its transcript with
  `jq` (the `input` of its hand-back `tool_use`) instead of retyping it.
- **Worktrees under review are off limits:** never remove or recreate a worktree while a reviewer may be reading or
  serving it; ask the director first.
- **Shot sets need a short trip:** cross-Spain trips look "framed" at the Spain view and hide framing bugs; every UI
  shot set includes a short trip (e.g. Jaca → Benasque) next to a long one.
- **No symlinked node_modules between worktrees:** when the target worktree is removed or reinstalled, every worktree
  pointing at it breaks (main's was emptied once). Each worktree runs its own `npm ci` or `cp -c` a copy.
- **Kill orphans when removing a worktree:** stop its dev servers and vitest runs first; an orphan vitest fork from a
  deleted worktree burned a core for hours.
- **One holder per phone, handed over explicitly:** the director names who holds each phone and takes it back before
  handing it on; other projects' sessions may also drive a shared phone, so ask them before a run. Two Twisty sessions and another project once drove the Huawei at the same time.
- **The maintainer's lock screen is private:** never unlock, swipe or dismiss it, and never screenshot while it or a
  notification may be on screen (check the foreground app before each screencap). A locked phone means stop and ask;
  a shot once caught notification previews and had to be deleted.
- **Experiments never touch shared data:** the bench takes `TWISTY_DATA` and `TWISTY_INTERIM`, and
  `node scripts/.build/candidates.js --data <dir>` a data folder; point them at a scratch dir instead of mutating the
  `app/public/data` symlink or `data/interim`. A worktree with a data symlink reads main's data, so `planner.spain`
  fails there until the stack's data lands: that is expected, not a regression.
- **A cause is measured, not inferred:** a report that says why a bench number moved names the run that shows it
  (e.g. which stop, which chain); an inferred cause once reached the maintainer and had to be retracted.
- **The maintainer's own app data stays:** on a phone the maintainer uses, never clear their trips, history or settings
  in Twisty to stage a test; use a fresh trip on top, or ask. A cleanup once wiped trips the maintainer had planned.
- **Stopping a heavy job:** kill the job's own process, then check the wrapper's status that its label is gone; a wrapper
  still waiting for a slot once outlived a kill and later took a slot for a build nobody wanted.
- **A pipeline change re-records the bench baseline in its own branch:** step 1 landed without it, and the gate on
  main went red once the shared data was rebuilt.
- **Gates run on the rebased branch before landing:** a branch green on its own base turned `npm run check` red on
  main after a rebase (the share button); the director runs the three gates on the rebased head, not the owner's run.
- **Live Nominatim checks are throttled by the script:** a comparison run of main's address search fired 22 requests
  back to back and Nominatim answered 429 to the machine's IP for at least half an hour (phones on the same network
  share it). Wait 1.5 s in the measuring script's own fetch, whatever the code under test does.
- **Scratch builds run under a timeout:** a pipeline build with new graph code hung at 100% CPU and held a heavy
  slot for 13 h overnight until another project asked; wrap every heavy job in `timeout` (a Spain build takes about
  20 min, so 45 min is plenty) and try new graph code on a small extract first.
- **A map-matching gap is a matcher suspect first:** a ride's "graph gap" at Torrebaja reached the ROADMAP and was
  retracted; the matcher had entered an edge at the wrong end and measured to vertices. Check the edge's stored
  geometry by segment before calling it a graph gap.
- **Play Protect blocks repeated debug installs on the Huawei:** about every 5-8 `adb install` of a debug APK it shows a
  dialog that blocks the install until a person closes it; an A/B pass that reinstalls per round overran its grant by
  an hour. Plan passes with as few installs as possible (all rounds of one build, then the other), and budget for it.
- **A landed dependency needs `npm ci` on main:** after street-search-2 added `@capacitor/geolocation`, main's own
  `node_modules` lacked it, so `npm run check` failed there and any `cp -c` copy of it was broken too. The director runs
  `cd app && npm ci` on main right after landing a branch that changes `package-lock.json`.
- **A bench in a copied `app/` needs its own git repo:** `run.js` reads `git rev-parse`, so a scratch copy without
  `git init` and a commit fails silently; a weight grid once ran for nothing.
- **A device scroll check reads the offset after every gesture batch:** a saved-rides pass reported "the list does
  not scroll" from two identical shots, after flings that went to the end and back; it was retracted. Read
  `scrollTop` and take a shot after each batch. A device script's first foreground check allows the launcher.
- **A SPIKE line is removed with an exact edit:** reverting a temporary hook with `git checkout <file>` also threw
  away an uncommitted fix in the same file, and a report claimed a change that was not in the build.
- **A capture agent never deletes inside its output folder:** it writes intermediates elsewhere. A review run's
  street-search shot was deleted by its capture agent and could not be retaken under the Nominatim cap.
- **A new graph rule is tried on a regional extract first:** a Pyrenees extract reproduced the Spain bench's C-28 and
  C-462 losses in about 2 minutes a build, so the cause was measured without a second 23-minute Spain build.
- **A threshold is set on the unit the rider sees:** 8 km on a candidate (a piece between junctions) dropped 63% of
  the great roads; on the twisty the road falls in, it dropped none of the found ones.
- **Headless captures settle only with focus emulation:** turn on `Emulation.setFocusEmulationEnabled`, hide UI with
  `visibility:hidden` (never `display:none`, the base map vanishes), shoot after several identical frames (network idle
  let shots through without the base map), and take the Spain view at dpr 1. A store run spent 2 h on 6 images without it.
- **A capture agent kills only its own browsers:** it stops the PIDs it launched (or their children), never a pattern
  over headless Chrome's flags; a store run's broad kills could take down other sessions' captures, other projects' too.
  A still screen does not prove the map is drawn: base tiles at the Spain view took over 15 s to paint after arriving.
- **A device script types like a finger:** wait about 1 s after tapping a field before sending keys; CDP keys sent
  400 ms after the tap raced the field's opening blur and left the search list closed, which read as a product bug.
- **`fastlane supply` cannot upload a listing before the app's first release:** it reads the track's release first and
  dies on `undefined method 'size' for nil`. `stores/src/play-listing.rb` uploads texts and images without one.
- **A profiling probe gets a fresh page:** reload the app between probe runs; a console.profile listener left in
  page memory added 250-290 ms to pointerdown and spoiled two traces of a 20-minute Huawei slot.
- **Check the phone's floor before setting a frame target:** on the Huawei one map redraw costs about 33 ms, so a
  scrub's p95 ≤ 33 target was out of reach before any fix; measure a plain redraw (still and panning) first.
- **Device drags start 40 px in from the edges on the Fold:** a swipe 6 px from the left edge is Samsung's back
  gesture; it sent Twisty to the background and a drag run came back empty.
- **EMUI has no `screenrecord`:** record the Huawei with a CDP screencast of the WebView (Twisty's frames only, no
  system UI). A run that called it still drove one drag and spoiled the fresh start.
- **A WebView storage change needs time before a force-stop:** a localStorage key removed and then force-stopped at
  once came back on relaunch; wait about 10 s before the cold relaunch.
- **A check removes what it injected:** hide CSS left in the page after an iPhone location check made the map look
  black to the maintainer, who reported it as a new bug. Remove injected styles when the check ends, before detaching.
- **A device soak restores storage in its own step:** the restore from the soak's backup runs whatever the soak did.
  When WebContent restarted mid-soak, the page reloaded under the script, which hung before its cleanup and left an
  experiment key and the run's trips on the maintainer's phone until restored by hand.
- **iOS 26 gives no screen capture from a Mac:** devicectl and idevicescreenshot fail; the WebKit inspector's
  `Page.snapshotRect` shows Twisty's page only. Anything outside the page (share sheet, Google Maps, prompts) is the
  maintainer's report.
- **Touch runs hide the map with `opacity: 0`, not `visibility: hidden`:** a hidden canvas passes touches through to
  the page, so MapLibre never saw a pan or long-press and the WebView selected text instead.
- **A device script's cleanup survives its guard:** pass-lib's guard calls `process.exit`, which skips `finally`;
  override it to throw so injected styles are removed.
- **The iPhone's inspector needs the cable:** `ios_webkit_debug_proxy` goes through usbmuxd; check `idevice_id -l`
  before an iOS pass and ask for USB first (the phone may be paired over the network only).
- **A phone handed to the maintainer is off limits:** when the director gives a tester build to the maintainer, it
  tells every session at once; nobody installs on that phone until the director releases it.
