# UX review round 2 (after Batch D) — 2026-10-14

UX review round 2, after Batch D, of branch `trip-editor` at 22a9e70 (worktree ~/code/twisty-editor), which contains everything on main.

- unfolding the Fold while a field has focus leaves a black band under the map.

## 3. New findings, most severe first

1. **Major: choosing A by touch drops focus instead of moving it to B.**
   - In emulation, `document.activeElement` is BODY at +0, 50, 200 and 500 ms after tapping the first row (`ux2/focus.mjs`; shot `p360-es-focus-after-A.png`), and typing goes nowhere. The rider has to tap B, and on a phone the keyboard drops in between.
   - Cause: rows pick on `onmousedown` without `preventDefault` (`PlaceSuggestions.svelte:40`), so the mousedown's default action steals the focus that `placeChosen` (`Panel.svelte:182-187`) just gave to B. The address row at `:55-56` already does `preventDefault`, and it keeps focus.
   - Fix: `onmousedown={(e) => { e.preventDefault(); list.onchoose(place) }}`.
   - Confirm on the Huawei that the keyboard stays up. Owner: frontend.
2. **Major: the editor closes under the rider when a plan lands.**
   - Repro (`ux2/yank.mjs`): from a ride, open the editor, toggle tracks, tap B and type "Granada". By 1.5 s the editor is closed, focus is on BODY, every keystroke is lost and B is unchanged. Shots `p360-es-st-06/07`.
   - Cause: the `fastestRide` effect sets `editorOpen = false` on every new result (`Panel.svelte:144-152`). On the Huawei the first tracks plan took 12 s in round 1, so this lands mid-typing. The spec says the tracks toggle keeps the editor open.
   - Fix: drop `editorOpen = false` and `optionsOpen = false` from that effect. `placeChosen` already closes the editor when the trip is complete, and Back or Escape close it otherwise. Keep `snapName = 'half'`.
   - Owner: frontend.
3. **Major: a posture change while a field has focus freezes the map at the old height.**
   - Unfolding 412 → 884 while typing gives `--app-height: 915px` on a 1104 px screen, and the map canvas stays 915 px tall.
   - This leaves a 189 px black band under the map, and it **stays after blur** until the next resize (`ux2/shots/pos2-unfold-blurred.png`, `pos-03-unfold-884-editor.png`).
   - Cause: `viewport.ts:9-16` holds the height whenever an input has focus and re-measures only on resize. The hold already existed on main, but the full-screen editor makes "a field has focus" the common state while the phone is folded.
   - Fix:
     - release the hold when `innerWidth` changes, since a keyboard never changes the width;
     - also call `update` on `focusout`.
   - Verify on the Fold. Owner: frontend.
4. **Minor: the editor opens to an empty screen.**
   - Tapping a name in the trip row shows the two fields, the chip and about 75 % empty navy (`360x780-es-default-trip-editor.png`), because the query equals the current value and gives no list.
   - Fix: show a first row "Use my location" (the action already exists) and the suggestions for the current label, so the screen offers a next step. Owner: ux-designer, then frontend.
5. **Minor: map labels show through the phone sheet.**
   - With blur off and 0.96 opacity, labels are readable behind the sheet: "Murcia" and "Cartagena" behind the bars, "Alacant" behind the badge (`ux2/shots/p360-es-st-03-planning.png`, `-st-07-…`), "Sevilla / Gibraltar / Tanger" behind the list (`360x780-es-long-full.png`).
   - Fix: on phones use `--surface-sheet-solid` or 0.985. Owner: frontend.
6. **Minor: the pinned footer ignores swipes.**
   - At peek the footer is 76 of 234 px, a third of the sheet, and an upward swipe there does nothing (flow log `footer drag up 366 → 366`).
   - Fix: give `.footer` `use:sheetDrag.handle`. The existing slop and `swallowClick` keep the button's tap. Owner: frontend.
7. **Minor: the start sheet at peek puts the chip flush against the bottom edge,** with 0 px under it (`ux2/shots/p360-es-01-start-peek.png`).
   - Fix: add 12 px plus the safe area under the start sheet's head. Owner: frontend.
8. **Minor: hover sticks on touch** in suggestion rows, twisty rows, clear, locate/swap and the secondary button (`PlaceSuggestions.svelte:112-115`, `RideSummary.svelte:235,304`, `PlaceField.svelte:215`, `Panel.svelte:587`).
   - The editor shot shows two highlighted rows (`360x780-es-editor-guadal.png`).
   - Fix: wrap these in `@media (hover: hover)`, as the slider already does. Owner: frontend.
9. **Minor: the pins note sits in the wrong place.** "Cada tramo lleva puntos de paso para que Google Maps…" sits under the **GPX** button and far from the Google button (`360x780-es-default-full.png`, `884x1104-es-default-ride.png`).
   - Fix: on phones put it right above the footer's Google button. On desktop put it directly above the sticky Google button. Owner: frontend.
10. **Minor: language buttons are 67×25** on the start sheet.
    - Fix: extend the hit area to 44 px with a `::before`. Owner: frontend.
11. **Minor: peek does not use the map it frees.** On a long trip the route stays in the top half with about 200 px of empty map below (`412x915-es-long-peek.png`).
    - This follows the spec ("refit only if hidden").
    - Optional fix: refit on settle at peek when the route fills less than about half of the padded height. Owner: frontend, ux-designer to confirm.
12. **Minor: the no-route error is a dead end.** It reads "No hay conexión por carretera entre estos dos lugares." with no next step (`ux2/shots/p360-es-st-01-no-route.png`).
    - Fix: add a "Cambiar llegada" button that focuses B. It needs an i18n key. Owner: frontend.

## 4. What works, don't break it

- **Sheet:** one full-height layer moved only by transform, with the main button pinned in a separate footer at every snap. The snap maths in `sheet.ts`: flick, nearest snap, rubber band, and snaps dropped when too close.
- **Headline:** above the slider, time on the left, two-line badge on the right, no wrap at 360 in Spanish.
- **Trip row:** two 44 px name buttons that open the editor on the right field. Back and Escape return to the same snap and the same ride.
- **Editor layout:** solid full screen, 52 px rows, inline list, chip hidden while the list is open.
- **Options chip:** quiet when off; earth tint plus "· Pistas" visible while closed when tracks are on.
- **Footer line for tracks:** the 2 km GPX threshold behaves as specified.
- **Fold side panel:** 360 px, clear of the hinge; fixed height while a ride shows, with the button pinned. The legend pill and the coloured route over the casing.
- **Refining state:** "La más rápida" plus placeholder bars, so the rider is never shown an empty sheet.

## Known limits

- **Not re-checked by me, as instructed:** the real keyboard, Huawei feel, the slider-step animation and drag performance (already traced on the phone).
- **Flick artefact:** some flicks in my runs that started within about 1 s of a previous settle did not snap. Event timestamps show the 100 ms gestures stretched to 1–2 s while SwiftShader re-rendered the map (`gest3.mjs` log), so I treat this as emulation, not a finding.
- **Device checks still needed:** findings 1 and 3 should be confirmed on the Huawei and the Fold.
