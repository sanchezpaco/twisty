# Review round 1 — 2026-10-13

Build: `main` 76b4a21 with fresh pipeline data, debug APK. Reviewers: `mobile-performance-engineer` (measured on the
Huawei P smart 2019), `ux-designer` (headless Chrome at 360×780, 412×915, 884×1104, 1440×900), `weekend-rider`
(360×780). Raw shots and data were in the director's scratchpad; numbers below are the ones that matter.

Maintainer decisions from the same day: phones are portrait-only; the status-bar area is painted in the app's colour
(edge-to-edge, no white bars). Quality is never traded for speed.

## Ranked findings

### Batch A — `app` session: phone basics and broken behaviour

1. **Blocker** — Route start, curves or finish land under the sheet; Spain framed small at launch. The map frames
   before the sheet is measured (`MapView.svelte:58-59`, `fitIfHidden` at `:155-159` tests unpadded bounds). Fix:
   `map.setPadding(viewPadding())` on every sheet-height change (read untracked), test against the padded rectangle,
   refit Spain once the sheet is measured.
2. **Blocker** — Trip lost when Android kills the app during the Google Maps hand-off. Persist from, to, stop and
   tracks; re-plan on restore.
3. **Major** — Portrait lock and edge-to-edge status bar in the app's colour (maintainer decision).
4. **Major** — Camera snaps back to a focused twisty on any sheet resize and ignores a new trip
   (`MapView.svelte:107-109`). Clear focus when the ride changes; read `sheetHeight` untracked.
5. **Major** — Glass blur missing in the build: the minifier keeps only `-webkit-backdrop-filter` on `.panel`
   (`Panel.svelte:216-217`, verified in `dist`). Drop the manual prefix; raise sheet surface opacity to ~0.94.
6. **Major** — B pin drawn ~30 px low: `.place-marker { position: relative }` overrides MapLibre's absolute
   positioning (`MapView.svelte:283-287`, verified).
7. **Major** — Soft keyboard resizes the WebView (114 ms + 311 ms stalls, 4× per trip). `windowSoftInputMode`
   `adjustNothing`, lift the sheet by the keyboard inset.
8. **Major** — Long-press menu closes on release (`MapView.svelte:71-72`); confirm on a device, ignore the click
   that ends a long-press.
9. **Major** — Touch targets: handle (10–22 px, missing from the `flex: none` list), slider bars, locate/swap 36 px,
   clear 26 px. Everything ≥ 44 px; the bars block is one drag area.
10. **Major** — Slider row jumps 29 px when switching to/from "fastest". Fixed height.
11. **Minor** — Touch copy says "right-click": pick copy by `(pointer: coarse)`; long-press wording.
12. **Minor** — Tooltip sticks after tap: `@media (hover: hover)` (`RideSlider.svelte:135`).
13. **Minor** — Attribution overlaps sheet content; distance "a 292 km" from the map centre; stat cards overflow at
    360; old route not dimmed while re-planning; Escape leaves unresolved text; rough error states.
14. **Minor** — Commit the regenerated Capacitor files (`capacitor.settings.gradle`, `capacitor.build.gradle`).

### Batch B — `routing` session: planning speed without changing results

1. **Blocker** — Madrid → Granada 7.4 s: 18 searches × 250–300 ms plus a 50 ms `Math.exp` pass over 884k edges
   before each. Fixes that keep results bit-identical: lazy weights (`Math.fround`), bidirectional Dijkstra, send
   the fastest route to the UI first. Expected 3.5–4 s; under 2 s likely needs an algorithmic change — plan it,
   don't cut appetites or refinements (they are slider stops).
   **Gate:** a test proving every option of a set of real trips is identical before and after.
2. **Major** — Tracks mode: release the roads-only planner after stacking, avoid duplicate copies.
3. **Minor** — `NodeLocator` string-keyed Map over 644k nodes (42 % of a 1.2 s init): numeric cells.
4. **Minor** — `make setup` Python ≥ 3.12 (ROADMAP Next up 4).

### Batch C — `app` + `routing`: launch and the twisty overlay

1. **Major** — Overlay at 8 s and a 1.28 s main-thread freeze: all 4,951 lines are serialised to MapLibre's single
   worker after `load`. Let the worker fetch a GeoJSON URL (or pre-tiled vector tiles that drop nothing), count from
   `meta.json`, add the source with the style. GIS engineer owns the export.
2. **Minor** — Pre-normalised place keys from the pipeline (first keystroke > 100 ms).
3. **Minor** — First 3D toggle: 428 ms shader stall; set terrain, wait for idle, then ease. Check one DEM source.
4. **Minor** — Slider step 40–65 ms: cache `Intl.NumberFormat`; draw the route from one upload.
5. **Measure** — `graph.bin` stored uncompressed in the APK (+15 MB); `setWorkerCount(2)`.

### Batch D — design work, needs a spec first (`ux-designer`, then `app`)

1. **Major** — Draggable sheet with snap heights (peek ~220 px, half, full).
2. **Major** — Full-height search mode on phones (suggestions fall under the keyboard).
3. **Major** — Unfolded Fold (884 px) gets the stretched phone sheet: floating side panel from ~700 px.
4. **Major** — Route view loses the curve legend; the route glows one colour even on "fluida" segments.
5. **Major** — Slider redraws the whole route from A on every stop: animate once per trip, then only the difference.
6. **Major** — Ride with tracks hides the main button when folded; 0.2 km of track flips it to GPX (threshold from
   `rider-safety`).
7. **Minor** — Badge and marker collisions (`cartographer`); summary chip truncation; "Carreteras" label;
   English wording ("km of twisties").
8. **Open** — "Incluir pistas" in the main flow vs an options chip.

### Pipeline / search (`routing`, GIS)

- Search ranking ignores proximity for prefixes ("Guadal" → Guadalajara before Guadalest); "near X" anchors are odd.
- Google mobile web shows coordinates instead of names and 137 km vs 124 km on desktop: investigate.

## What works, don't break it

The cinematic route over the dark hillshade; instant offline town search; planning in a worker with a responsive
UI; tracks.bin loaded lazily; the slider's trade-off at a glance and its default stop; the segment list in rider
language and fly-to; the Google hand-off matching Twisty within 1–3 km; the folded sheet's content; the Spanish copy;
the desktop panel.
